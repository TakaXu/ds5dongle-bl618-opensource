# P1 分区与启动静态审计

日期：2026-09-26。完成只读工具及静态审计，G1 尚未通过。

## 修改与原因

新增 tools/audit_partition.py 检查 Flash 容量边界、4 KiB 对齐、分区表/分区重叠与双 FW 槽位。新增 tools/test_partition.py，4 项测试通过：现有冲突、边界差一字节、分区表冲突、缺少备用槽。

```powershell
python tools/test_partition.py
python tools/audit_partition.py firmware/lctech616/partition_cfg_4M_nosec.toml --flash-size 0x400000
```

现有模板检查返回 1，原因是 FW[1] 与 mfg[0] 重叠，属于预期。容量参数是假设，不是设备探测。工具仅分析 TOML，不解码设备分区二进制、不覆盖全部 SDK 格式合法性；ota_ready 始终为 false，不能由布局检查通过推定硬件就绪。

## 分区证据

两份模板地址布局一致：PT 位于 0xE000/0xF000，FW[0] 为 [0x10000,0x210000)，FW[1] 为 [0x210000,0x378000)，与 mfg 完全重叠。PSM、KEY、DATA、factory 位于尾部，应用升级不能擦除。

备用槽 0x168000 小于主槽 0x200000。上限必须包含完整镜像头、对齐与附加数据，不能只判断代码段大小。

SDK components/utils/bflb_mtd/bflb_boot2.c 的 bflb_update_mfg_ptable 在地址相同时清除 mfg 条目名称并更新表；这不证明真实设备 mfg 数据可以丢弃，不能直接用作安全迁移。

## 启动恢复证据

固定 SDK examples/boot2_isp/main.c 在 BFLB_SP_BOOT2_ROLLBACK 下既有镜像解析失败回退，也有 age 高字节 retry_flag：大于 0xF0 时递减并更新分区表，仍非零且不大于阈值则回退。

源码存在重试逻辑，不等于预编译 boot2_bl616_isp_release_v8.1.8.bin 包含它。需要核对二进制来源、构建宏、元数据更新失败处理及实际启动行为。

应用侧 bflb_boot2_update_ptable 切换 active_index 并递增 age，没有建立完整试启动/看门狗/健康确认契约。合法但卡死的镜像是否能触发重启、耗尽重试并可靠回退仍待设计和实测。防降级 eFuse 与故障恢复不是同一功能，首版不写不可逆 eFuse。

## 当前决定及下一步

保留现有业务与分区，不直接开放备用区写入，不冻结 OTA 报告 ID、包格式和签名协议。先核实板型、Flash、当前版本/FS或HS、BOOT及串口恢复条件，备份真实 Flash/配置并确认 mfg 用途，再选择复用或维护 Boot2。

用户没有备用板。依照原开发计划，不在唯一日常设备执行破坏性断电故障注入；G0/G1 硬件项保持未通过。获得可恢复测试条件后再实施升级服务和网页更新状态机。本次不是已支持网页 OTA 的固件交付。
